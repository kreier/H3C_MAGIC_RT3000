Qualcomm IPQ50xx Boot Process & Stages

The RT3000's 128 MiB flash starts at 0x00000000 with 0:SBL1 (Secondary Boot Loader 1) — because the router does not actually start booting from flash. Execution begins inside immutable Boot ROM baked into the Qualcomm silicon itself.

The 5 Boot Stages (Silicon ROM → OpenWrt)

When power is applied, the IPQ5000 / IPQ5018 walks through five strictly ordered stages, each initializing more of the hardware and handing off control to the next:

Stage 0PBL
Immutable Silicon Boot ROM (inside SoC) Not on NAND flash

Primary Boot Loader (PBL) is mask-programmed permanently inside the Qualcomm CPU silicon. At power-on, PBL reads hardware boot-strap pins (SPI NAND vs. NOR/eMMC), brings up a minimal SPI-NAND controller, and loads 0:SBL1 from flash offset 0x00000000 into internal on-chip SRAM (OCIMEM). If flash is empty or 0:SBL1 is corrupt, PBL falls back to Qualcomm Emergency Download (EDL / 9008).

Stage 10:SBL1
mtd0 · 0x00000000 (512 KiB) Single copy (not A/B mirrored)

Secondary Boot Loader 1 is the first code read from flash. It reads 0:CDT (mtd8) and 0:TRAINING (mtd14) to initialize the external 256 MiB DDR RAM, parses the 0:MIBIB (mtd1) partition table, and reads 0:BOOTCONFIG / 0:BOOTCONFIG1 (mtd2/mtd3) to know which mirrored slot (0 or 1) to load for every subsequent stage.

Stage 20:QSEE & DEVCFG
mtd4–mtd7 (2.50 MiB total) Fail-safe A/B mirror

Qualcomm Secure Execution Environment (ARM TrustZone) plus its hardware security configuration (0:DEVCFG). Loaded by SBL1 into protected memory, QSEE remains resident while U-Boot and Linux run, serving Secure Channel Manager (SCM) calls for clocks, crypto, Wi-Fi/NSS authentication, and fuse access.

Stage 30:APPSBL (U-Boot)
mtd11 + mtd12 (2.50 MiB total) Fail-safe A/B mirror

Applications Processor Secondary Boot Loader — this is where Das U-Boot (our replacement IPQ50XX-Uboot / uBootKit) runs. It reads 0:APPSBLENV (mtd10) and 0:BOOTCONFIG, auto-detects the SPI NAND chip & ECC mode, checks the hardware RESET button (for Slot 1 / Slot 2 switching or the 192.168.10.1 Web Rescue UI), and boots the Linux kernel from the selected UBI slot.

Stage 4Linux / OpenWrt
mtd15 rootfs / mtd16 rootfs_1 (40 + 40 MiB) User-selectable Dual-Boot

U-Boot loads the kernel FIT image from the chosen UBI volume (rootfs = Slot 1 Stock H3C, or rootfs_1 = Slot 2 OpenWrt 21.02.7). Linux mounts SquashFS + the writable UBIFS overlay, loads Wi-Fi radio calibration from 0:ART (mtd13), and starts NSS hardware offload and LuCI.

Why Flash Starts at SBL1 (and Why SBL1 Isn't Mirrored)

  • Where boot really begins: Because Stage 0 (PBL) lives inside the CPU silicon's read-only memory, the first binary stored on external NAND flash is Stage 1 — hence Secondary Boot Loader (0:SBL1).
  • Why there is no 0:SBL1_1: Qualcomm's A/B selector (0:BOOTCONFIG) is parsed by SBL1, not by PBL. PBL itself only knows how to search fixed boot blocks at the start of NAND (relying on Qualcomm's NAND page/block redundancy rather than an A/B partition table) to load 0:SBL1. In normal router life, 0:SBL1 is written once at the factory and should never be touched when installing OpenWrt.

Why We Always Write mtd12 Before mtd11
Because 0:BOOTCONFIG points to slot 0 (mtd11 / 0:APPSBL) on a stock RT3000, flashing mtd12 (0:APPSBL_1) first and verifying its SHA-256 readback tests NAND writes against the inactive mirror while keeping your working bootloader untouched. Only once mtd12 passes 100% do we mirror the same verified image to mtd11.
