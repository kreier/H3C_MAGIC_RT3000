Hardware & Board Variants (HW-A / B / C / D)

The H3C Magic RT3000 shares its casing and VER.A label across multiple different PCBs. Always identify your exact Hardware Group from 0:CDT and 0:ART before flashing U-Boot or OpenWrt.

Core Hardware Specifications

  • CPU: Qualcomm IPQ5000 (HW-B / HW-D) or IPQ5018 (HW-A / HW-C), dual Cortex-A53 running a 32-bit ARMv7 OS.
  • Switch: QCA8337 (HW-A / B / D) or RTL8367S (HW-C) — 1× Gigabit WAN + 3× Gigabit LAN.
  • Memory: 256 MiB RAM.
  • Storage: 128 MiB SPI NAND flash (1,024 erase blocks × 128 KiB, 2,048 B page size; e.g., GigaDevice GD5F1GQ5REYIG or Winbond W25N01GW).

Identifying Your Hardware Group

Do Not Trust the Case Sticker
The stock web UI string VER.A and case stickers (D0 / B0 / C1) do not reliably identify your board group. Flashing the wrong group (HW-A–HW-D) can brick the router and require a UART/TTL adapter to recover.

Read /proc/device-tree/model, the 5-byte platform tuple in 0:CDT (mtd8 @ 0x1a), and—if machid is 0x08040000—the 5 GHz calibration header in 0:ART (mtd13 @ 0x26800):

Hardware Group Device Tree / FDT CDT Tuple (0x1a..0x1e) → machid SoC & Switch 0:ART @ 0x26800 (+0x00, +0x3a, +0x45)
HW-AAP-MP03.102 08 04 00 01 → 0x08040001IPQ5018 + QCA8337—
HW-BAP-MP02.102 08 04 00 00 → 0x08040000IPQ5000 + QCA833701 00 04 04, 0x50, 0x01 (no external 5 GHz FEM)
HW-CAP-MP03.1-C202 08 04 01 01 → 0x08040101IPQ5018 + RTL8367S—
HW-DAP-MP02.102 08 04 00 00 → 0x08040000IPQ5000 + QCA833701 00 04 04, 0x60, 0x09 (external 5 GHz FEM, e.g. NX30)

For this project's RT3000 (verified from firmware/old_firmware.7z):

  • 0:CDT tuple is 02 08 04 00 00 → machid = 0x08040000 (AP-MP02.1).
  • 0:ART @ 0x26800 has header 01 00 04 04, +0x3a = 0x50, +0x45 = 0x01 → no external 5 GHz FEM → HW-B.

Read-Only Probe Commands

Run inside debugshell on the router (or automate everything from 192.168.10.3 with python3 scripts/rt3000_helper.py probe):

# 1. Kernel, device tree model, and MTD partition layout
uname -a
cat /proc/device-tree/model; echo
cat /proc/mtd
fw_printenv

# 2. Board machid from 0:CDT (mtd8) and 5 GHz FEM flag from 0:ART (mtd13 @ 0x26800)
dd if=/dev/mtd8 bs=2048 count=1 2>/dev/null | dd bs=64 count=1 2>/dev/null | hexdump -C
dd if=/dev/mtd13 bs=2048 skip=77 count=1 2>/dev/null | dd bs=80 count=1 2>/dev/null | hexdump -C

# 3. NAND geometry, OOB size, and ECC strength
dmesg | grep -iE "nand:|spi|mtd|ipq|switch|qca|rtl"
for f in name writesize erasesize oobsize ecc_strength; do
    printf "%-14s: %s\n" "$f" "$(cat /sys/class/mtd/mtd0/$f 2>/dev/null)"
done

NAND Chip & ECC Auto-Detection

With IPQ50XX-Uboot v0.2.0+, there is only one image per Hardware Group (h3c-hw-a.mbn … h3c-hw-d.mbn). U-Boot automatically detects the SPI NAND manufacturer/chip ID and ECC mode (4-bit vs 8-bit) at boot and prints the exact chip name on the Web Rescue page.

Empty dmesg | grep -i nand Output?
The router's small kernel ring buffer rolls over after some uptime and evicts early boot nand: messages. This does not matter for IPQ50XX-Uboot v0.2.0+. If you still want to inspect the exact chip ID before flashing, reboot the router, wait ~35 seconds, and run rt3000_helper.py probe immediately.
